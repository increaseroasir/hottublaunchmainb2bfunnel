## 1. NEW FINDING — the deployed /check-territory form cannot submit

The commit running in prod (`4ddfded`) has this in the page's inline `value()`:

```js
return (input instanceof HTMLInputElement || input instanceof HTMLSelectElement) ? input.value.trim() : '';
```

`form.elements.namedItem('isOwner')` returns a **RadioNodeList** (two radios
share the name), which fails both instanceof checks → `isOwner` and
`monthlyVolume` always read `''` → `validate()` always returns false →
`event.preventDefault()` → **submit is silently blocked for every visitor**.

Proof (Playwright against a build of `4ddfded`, every field filled correctly):

```
OLD FORM (prod code): completely valid input, submit clicked
  POST to /api/lead observed: false
  still stuck on: http://127.0.0.1:8790/check-territory
  => CONFIRMED: the deployed check-territory form cannot submit in a browser
```

If paid traffic is on `/check-territory` right now, applicants cannot apply.
The Lane B rewrite fixes it (radio-safe `value()`); the fix is browser-proven
below. **This makes deploy urgent.**
